# SPEC-016: Interactive Installer (Cursor, OpenCode, Claude Code)

**Scope:** `ctxlite install` — configure ctxlite in Cursor, OpenCode, Claude Code, and Claude Desktop (global or project scope)  
**Depinde de:** SPEC-012–014 (opencode plugin, MCP server, CLI)  
**Agent target:** Cursor  
**Status:** `[x] Done`

---

## Problem

`npm install` does not modify tool config files. Users must manually edit JSON in different locations per tool. This spec adds an interactive (or flag-driven) installer that merges ctxlite into the correct config files.

---

## Config file reference (researched)

| Tool | Scope | Config path | Schema |
|------|-------|-------------|--------|
| **Cursor** | global (user) | `~/.cursor/mcp.json` | `{ "mcpServers": { "ctxlite": { "command", "args" } } }` |
| **Cursor** | project | `<project>/.cursor/mcp.json` | same |
| **OpenCode** | global (user) | `~/.config/opencode/opencode.json` | `{ "plugin": ["@ctxlite/opencode", ...] }` |
| **OpenCode** | project | `<project>/opencode.json` | same |
| **Claude Code** | global (user) | `~/.claude.json` | top-level `{ "mcpServers": { ... } }` |
| **Claude Code** | project | `<project>/.mcp.json` | `{ "mcpServers": { ... } }` |
| **Claude Desktop** | global only | macOS: `~/Library/Application Support/Claude/claude_desktop_config.json` | `{ "mcpServers": { ... } }` |
| | | Windows: `%APPDATA%/Claude/claude_desktop_config.json` | |
| | | Linux: `~/.config/claude-desktop/claude_desktop_config.json` | |

**Notes:**

- Cursor project config overrides global for the same server name.
- OpenCode also supports `opencode plugin @ctxlite/opencode -g`; installer edits JSON for consistency across tools.
- Claude Code does **not** read MCP from `~/.claude/settings.json` — use `~/.claude.json` (user) or `.mcp.json` (project).
- Claude Desktop is separate from Claude Code CLI.

**ctxlite entries written by installer:**

MCP tools (Cursor, Claude Code, Claude Desktop):

```json
{
  "mcpServers": {
    "ctxlite": {
      "command": "npx",
      "args": ["-y", "@ctxlite/mcp"]
    }
  }
}
```

OpenCode plugin:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["@ctxlite/opencode"]
}
```

## CLI: `@ctxlite/cli`

Rename package from `ctxlite` → `@ctxlite/cli` (unscoped name taken on npm).

```bash
npx @ctxlite/cli install
ctxlite install --tool cursor --scope global
ctxlite install --tool opencode,claude-code --scope project
ctxlite install --tool all --scope global --yes
ctxlite install --remove --tool cursor --scope global
ctxlite install --dry-run --tool all --scope global
```

### Flags

| Flag | Description |
|------|-------------|
| `--tool <id>` | `cursor`, `opencode`, `claude-code`, `claude-desktop`, `all` (comma-separated) |
| `--scope <scope>` | `global` (user) or `project` |
| `--project-dir <path>` | Project root for `project` scope (default: `cwd`) |
| `--yes`, `-y` | Skip confirmation |
| `--dry-run` | Print planned changes, do not write |
| `--remove` | Remove ctxlite entries instead of adding |
| `--help`, `-h` | Help |

### Interactive mode

When `--tool` is omitted, prompt:

1. Which tools? (multi-select)
2. Scope: global or project?
3. Confirm before write (unless `--yes`)

## Implementation

### `@ctxlite/core` — `src/install/`

- `paths.ts` — resolve config paths per OS (`homedir`, `platform`, `projectDir`)
- `targets.ts` — map `(tool, scope)` → `{ filePath, kind: "mcp" | "opencode" }`
- `merge.ts` — read JSON (or `{}`), merge/remove ctxlite entry, write with `JSON.stringify(_, null, 2)`
- `run.ts` — `install()`, `uninstall()`, `plan()` returning `{ path, action, created }[]`

Rules:

- Never delete unrelated keys or other MCP servers / plugins.
- Create parent directories (`mkdir recursive`).
- Idempotent: running install twice is a no-op (report `[skip]`).
- Preserve valid JSON; on parse error, fail with clear message.

### `@ctxlite/cli`

- Route subcommands: `stats`, `install`
- Delegate to `@ctxlite/core/install`
