# SPEC-012: @ctxlite/opencode — OpenCode Plugin

**Package:** `@ctxlite/opencode`  
**Scope:** Plugin OpenCode care injecteaza instructiuni de conciseness in system prompt si expune tool `get_stats`  
**Depinde de:** SPEC-010 (monorepo), SPEC-011 (@ctxlite/core)  
**Agent target:** Cursor  
**Status:** `[x] Done`

---

## Context si limitari ale plugin API-ului

Dupa analiza API-ului OpenCode, avem urmatoarele hook-uri relevante:

```
experimental.chat.system.transform  → modifica system prompt INAINTE de request
                                      input: { sessionID, model }
                                      NU primeste textul userului

chat.message                        → primeste mesajul dupa system prompt
                                      input: { message, parts }
                                      POATE modifica mesajul

tool.execute.before / after         → inainte/dupa executia unui tool
event                               → lifecycle events (session.created, session.idle etc)
```

**Limitare importanta:** `experimental.chat.system.transform` nu primeste textul userului — il primeste doar `chat.message` care ruleaza dupa ce system prompt-ul e deja construit.

**Implicatie pentru trimming:** Nu putem face BM25 trimming pe context *inainte* ca requestul sa plece la API prin hook-uri — OpenCode nu expune messages array-ul complet ca mutable in niciun hook.

**Ce facem in schimb — doua strategii:**

1. **`experimental.chat.system.transform`** → injecteaza instructiuni de conciseness in system prompt (garantat functional, zero risc)
2. **`get_stats` tool** → modelul il poate apela explicit pentru stats

**BM25 trimming** → disponibil ca tool explicit `trim_context` pe care userul sau modelul il apeleaza manual, nu automat.

## `system-prompt.ts`

```ts
/**
 * Instructiuni injectate in system prompt la fiecare request.
 * Ghideaza modelul sa fie mai concis si sa consume mai putini tokens.
 *
 * Principiu: instructiuni negative clare (ce SA NU faca)
 * sunt mai eficiente decat instructiuni pozitive vagi.
 */
export const CONCISENESS_INSTRUCTIONS = `
## Token efficiency (ctxlite)

When responding, apply these rules to reduce token usage:

- Skip preamble: never start with "Great question!", "Sure!", "Of course!", 
  "I'll help you with that", or similar filler phrases.
- Skip recap: do not restate what the user asked before answering.
- Skip sign-off: do not end with "Let me know if you need anything else!", 
  "Hope this helps!", "Feel free to ask!", or similar.
- Skip obvious reasoning: if the implementation is straightforward, 
  write the code — don't narrate the plan first.
- Prefer inline comments over long explanations: explain tricky parts 
  with a comment in the code, not a paragraph before it.
- Be direct on errors: state what's wrong and how to fix it. 
  Don't apologize or over-explain why it happened.

These rules apply to all responses. Code quality and correctness 
are not affected — only unnecessary verbosity is reduced.
`.trim()

/**
 * Returneaza instructiunile formatate pentru injectare in system prompt.
 * Separat de restul system prompt-ului cu un newline.
 */
export function buildSystemPromptAddition(): string {
  return "\n\n" + CONCISENESS_INSTRUCTIONS
}
```

## `tools.ts`

```ts
import { tool } from "@opencode-ai/plugin"
import { StatsStore } from "@ctxlite/core"
import { getStatsDbPath } from "./stats-path.js"

/**
 * Tool `get_stats` — returneaza statisticile curente ale sesiunii.
 * Modelul il poate apela explicit cand userul cere stats.
 */
export const getStatsTool = tool({
  description: `Returns ctxlite token savings statistics for the current session or a specified period.
Call this when the user asks about token usage, savings, costs, or ctxlite performance.
Returns a formatted report with: total requests, tokens saved, estimated cost saved.`,

  args: {
    period: tool.schema
      .enum(["session", "today", "7d", "30d", "all"])
      .optional()
      .describe("Time period for stats. Default: today"),
  },

  async execute({ period = "today" }) {
    let store: StatsStore | null = null

    try {
      store = new StatsStore(getStatsDbPath())

      const since = periodToTimestamp(period)
      const summary = store.summary(since)

      if (summary.totalRequests === 0) {
        return `## ctxlite stats — ${period}\n\nNo requests recorded yet for this period.`
      }

      const savedK = summary.tokensSaved >= 1000
        ? `${(summary.tokensSaved / 1000).toFixed(1)}K`
        : `${summary.tokensSaved}`

      return [
        `## ctxlite stats — ${period}`,
        ``,
        `**Requests:** ${summary.totalRequests} total, ${summary.trimmedRequests} trimmed`,
        `**Tokens saved:** ${savedK}`,
        `**Estimated cost saved:** $${summary.costSaved.toFixed(4)}`,
        `**Avg latency:** ${summary.avgLatencyMs}ms`,
      ].join("\n")
    } catch (err) {
      return `ctxlite stats unavailable: ${err instanceof Error ? err.message : String(err)}`
    } finally {
      store?.close()
    }
  },
})

/**
 * Tool `trim_context` — trimmeaza explicit o lista de fisiere.
 * Util cand userul vrea sa reduca manual contextul inainte de un request mare.
 */
export const trimContextTool = tool({
  description: `Analyzes a list of files and returns only the most relevant ones for the current task.
Use this before a large refactoring or analysis task to reduce token usage.
Provide the files you're considering including and your current task description.`,

  args: {
    files: tool.schema
      .array(
        tool.schema.object({
          path: tool.schema.string().describe("Relative file path"),
          content: tool.schema.string().describe("File content"),
        }),
      )
      .describe("Files to analyze"),
    query: tool.schema
      .string()
      .describe("Description of the current task"),
    maxTokens: tool.schema
      .number()
      .optional()
      .describe("Maximum tokens budget for selected files. Default: 4096"),
  },

  async execute({ files, query, maxTokens = 4096 }) {
    const { trimFiles, estimateTokens } = await import("@ctxlite/core")

    const codeFiles = files.map((f) => ({
      path: f.path,
      content: f.content,
      language: f.path.split(".").pop() ?? "",
      tokens: estimateTokens(f.content),
    }))

    const result = trimFiles(codeFiles, query, { maxTokens })

    if (result.tokensSaved === 0) {
      return `All ${files.length} files are relevant — no trimming needed.`
    }

    const selectedPaths = result.files.map((f) => `- \`${f.path}\``).join("\n")
    const excludedPaths = codeFiles
      .filter((f) => !result.files.find((s) => s.path === f.path))
      .map((f) => `- \`${f.path}\``)
      .join("\n")

    return [
      `## trim_context result`,
      ``,
      `**Selected** (${result.filesOut}/${result.filesIn} files, ${result.tokensOut} tokens):`,
      selectedPaths,
      ``,
      `**Excluded** (saved ${result.tokensSaved} tokens, -${Math.round(result.trimRatio * 100)}%):`,
      excludedPaths,
    ].join("\n")
  },
})

// ── helpers ──────────────────────────────────────────────────────────────────

function periodToTimestamp(period: string): number {
  const now = Math.floor(Date.now() / 1000)
  switch (period) {
    case "session":
      // "session" = ultima ora (aproximatie — plugin-ul nu stie cand a pornit OpenCode)
      return now - 3600
    case "today": {
      const d = new Date()
      d.setHours(0, 0, 0, 0)
      return Math.floor(d.getTime() / 1000)
    }
    case "7d":
      return now - 7 * 86400
    case "30d":
      return now - 30 * 86400
    case "all":
      return 0
    default:
      return now - 86400
  }
}
```

## `index.ts` — Plugin entry point

```ts
import type { Plugin } from "@opencode-ai/plugin"
import { buildSystemPromptAddition } from "./system-prompt.js"
import { getStatsTool, trimContextTool } from "./tools.js"

/**
 * ctxlite OpenCode plugin
 *
 * Ce face:
 * 1. Injecteaza instructiuni de conciseness in system prompt
 *    (reduce tokens prin ghidarea modelului sa evite verbozitate)
 * 2. Expune tool `get_stats` pentru raportare token savings
 * 3. Expune tool `trim_context` pentru trimming explicit
 *
 * Ce NU face:
 * - Nu intercepteaza HTTP traffic
 * - Nu face caching (nu are acces la request/response raw)
 * - Nu face trimming automat (OpenCode nu expune messages array ca mutable)
 */
const CtxlitePlugin: Plugin = async (_ctx) => {
  return {
    // ── Hook 1: System prompt injection ───────────────────────────────────
    // Injecteaza instructiuni de conciseness la fiecare request.
    // Documentatie: https://opencode.ai/docs/plugins/
    "experimental.chat.system.transform": async (_input, output) => {
      const addition = buildSystemPromptAddition()
      // output.system este string-ul system prompt-ului curent
      // Il extindem cu instructiunile noastre
      if (typeof output.system === "string") {
        output.system += addition
      }
    },

    // ── Tools disponibile modelului ────────────────────────────────────────
    tool: {
      get_stats: getStatsTool,
      trim_context: trimContextTool,
    },

    // ── Hook 2: Log session events ─────────────────────────────────────────
    event: async ({ event }) => {
      // Logam session.idle pentru a marca sfarsitul unei sesiuni in stats
      if (event.type === "session.idle") {
        // In v1: doar console.error pentru debug, nu logam in SQLite
        // (nu avem usage data disponibila din acest event)
        console.error("[ctxlite] session idle")
      }
    },
  }
}

export default CtxlitePlugin
```

## Ce vede userul

**La fiecare sesiune OpenCode** — system prompt-ul contine automat instructiunile de conciseness. Modelul raspunde mai scurt fara filler.

**Cand vrea stats:**
```
User: ctxlite stats
Model: [apeleaza get_stats tool]
       ## ctxlite stats — today
       Requests: 47 total, 12 trimmed
       Tokens saved: 34.2K
       Estimated cost saved: $0.1026
       Avg latency: 0ms
```

**Cand vrea trimming explicit:**
```
User: trim contextul inainte sa refactorizez
Model: [apeleaza trim_context cu fisierele din context]
       ## trim_context result
       Selected (3/12 files, 1,240 tokens):
       - `auth/login.ts`
       - `auth/session.ts`
       - `types/user.ts`
       Excluded (saved 8,760 tokens, -88%):
       - `render/template.ts`
       ...
```

## Testing manual (nu vitest)

Plugin-ul nu poate fi testat cu vitest — depinde de `@opencode-ai/plugin` runtime.

**Test procedure:**

1. Build plugin:
```bash
cd packages/opencode
npm run build
```

2. Link local:
```bash
npm link
```

3. Adauga in `opencode.json`:
```json
{
  "plugin": ["file:///path/to/ctxlite/packages/opencode/dist/index.js"]
}
```

4. Porneste OpenCode si verifica:
```bash
opencode
# In TUI:
# > ctxlite stats
# → ar trebui sa apara raportul
```

5. Verifica system prompt:
```bash
# In TUI, dupa primul mesaj:
# > show me your system prompt
# → ar trebui sa apara "Token efficiency (ctxlite)"
```

## Testele unitare pentru logica pura (in `@ctxlite/core`)

Logica de trimming si stats e in `@ctxlite/core` si e testata acolo (SPEC-011).  
Plugin-ul e un thin wrapper — nu are logica proprie de testat.

Singurul lucru testabil izolat din plugin:

```ts
// packages/opencode/src/system-prompt.test.ts
import { describe, it, expect } from "vitest"
import { buildSystemPromptAddition } from "./system-prompt.js"

describe("buildSystemPromptAddition", () => {
  it("starts with newlines for separation", () => {
    const addition = buildSystemPromptAddition()
    expect(addition.startsWith("\n\n")).toBe(true)
  })

  it("contains key instruction keywords", () => {
    const addition = buildSystemPromptAddition()
    expect(addition).toContain("preamble")
    expect(addition).toContain("recap")
    expect(addition).toContain("sign-off")
  })

  it("is idempotent — same output every call", () => {
    expect(buildSystemPromptAddition()).toBe(buildSystemPromptAddition())
  })
})
```
