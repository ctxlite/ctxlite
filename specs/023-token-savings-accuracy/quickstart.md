# Quickstart: Validate Token Savings Accuracy

**Feature**: `specs/023-token-savings-accuracy/`  
**Date**: 2026-07-12

Prerequisites, commands, and expected outcomes to verify this feature end-to-end. Implementation details live in `tasks.md` (generated by `/speckit-tasks`).

## Prerequisites

```bash
cd ctxlite
npm install
npm run build
```

## 1 — Run unit tests (fast sanity)

```bash
npm run typecheck && npm test
```

**Expected**: All packages pass; new/updated tests cover:
- OpenCode compress `upstream` = real tool name
- `precall (est.)` label in stats breakdown
- Hook/cursor-hook `upstream` (from `022`, regression guard)

## 2 — Run the deterministic benchmark suite

```bash
npm run bench
```

**Expected** (after implementation):
- Exit code `0`
- `bench/results/<timestamp>/report.txt` ends with `Regression Verdict: PASS`
- `summary.json` → `baselineComparison.measuredSavingsPercent` ≥ baseline × 1.15
- `regressionVerdict.failures` is empty

### Read the report

```bash
cat bench/results/*/report.txt | tail -30
```

Check:
- **Measured savings %** line present and above pinned baseline +15%
- Per-mechanism totals match `byMechanism` in `summary.json`
- All `ctxlite-all/<taskId>` lines show `pass rate 100%`

## 3 — Verify logging accuracy (SC-002)

Inspect a single run with attribution:

```bash
cat bench/results/*/runs/ctxlite-all::compress-large-output.json
```

**Expected**:
- `mechanismAttribution.compress` > 0

## Failure triage

| Symptom | Likely cause |
|---------|----------------|
| `measuredSavingsPercent` below gate | Compress/compact thresholds too conservative; check `tool-output-compress.ts` / `context-prune.ts` |
| `loggingAccuracy` delta > 10% | Mismatch between hook logging and `estimateTokens()` — check `logOptimizationSavings` call sites |
| `upstream: "opencode"` in compress rows | OpenCode `tool-compress-hook.ts` not fixed |
| Cursor compress scenario fails | Built-in compress unavailable — scenario should skip, not fail |
